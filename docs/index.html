Typed, calibrated decisions for Java

Turn "which team handles this ticket?" into a Java type. You get a valid value, probabilities you can rely on, and a gate that sends uncertain cases to a human, from a small local language model or a classifier trained on your own data.

Most questions to an LLM have a few right answers

"Which team handles this ticket", "is this spam", "how relevant is this document": the answer is one of a handful of options. Generating free text for that is slow, hard to parse and impossible to trust. dukehoff-decide asks for exactly that choice and tells you how sure it is.

Always a valid value

Enums, booleans and scales become typed fields. No parsing, no hallucinated categories, no retries.

Probabilities you can rely on

Calibrated on a few hundred labelled cases, so 90% confidence means about 90% correct.

A gate for the unsure cases

Decide the confident cases automatically and send the rest to a human, with a threshold measured on your data.

How it works

One annotated type, one pluggable backend, one calibration step.

01 · Schema

Type → questions

Every field becomes "pick one of N options": yes/no, one option per enum constant, one per @Scale step.

02 · Backend

Scores per option

A ScoringBackend returns log-probabilities per option: a language model's next token, or a trained classifier.

03 · Calibration

Honest confidence

Calibration.fit fits temperature and per-option bias, reports accuracy, ECE, confusions and the threshold for a target accuracy.

04 · Binding

Typed value + gate

Calibrated probabilities become the record, per-field distributions, and a confident or uncertain outcome.

Start with a language model, switch when the labels are there

Calibration, gating and diagnostics are the same for every backend, so the code that uses the decisions never changes.

dukehoff-decide-openai

Small language model

Works from day one with only the question and option texts. Any OpenAI-compatible server with logprobs: llama.cpp, Ollama, vLLM, LM Studio.

dukehoff-decide-classifier

Word counts + logistic regression

LinearClassifier trains in seconds on a few thousand labelled cases, scores in well under a millisecond and needs no server and no dependencies.

dukehoff-decide-embedding

Sentence embeddings + logistic regression

EmbeddingClassifier on a frozen embedding model: best on longer texts written by people, and a little ahead of word counts on German text.

Combine them

Word counts and embeddings are unsure about different cases. A Cascade lets the cheap backend decide what it is sure about and passes only the rest on, in one batch per stage. An Ensemble averages its parts and is calibrated as a whole.

  • Each stage calibrated on its own, with its own threshold.
  • The embedding is only computed for the cases the linear model is unsure about.
  • A language model fits as the last stage, for the few cases both classifiers leave.
Cascade
Cascade<Triage> triage = Cascade.of(
        linearTask.requireConfidence(0.9),
        embeddingTask.requireConfidence(0.9));

Outcome<Triage> outcome = triage.decide(state);
List<Outcome<Triage>> all = triage.decideAll(inbox);

// or one backend, calibrated as a whole
ScoringBackend both = Ensemble.of(linear, embedding);
